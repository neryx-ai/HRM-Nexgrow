# Plan: Filtrar historial de asistencia por empleado

## Problema
Cuando un usuario con rol `"empleado"` accede a `/dashboard/asistencia`, ve el historial de asistencia de **todos** los empleados de todas las sucursales, además de controles administrativos (filtros, corte automático, registro manual).

## Objetivo
El empleado debe ver **solo su propio historial** y la UI debe ocultar los controles de administrador.

## Patrón de referencia
El módulo de vacaciones ya implementa este patrón:
- `getResumenVacaciones()` (`src/actions/vacacion.actions.ts:557-633`) detecta el rol, consulta `empleado.id` vía `userId`, filtra los datos y retorna `esEmpleado: true/false`
- La página pasa `esEmpleado` al componente cliente, que condiciona la UI

---

## Cambios necesarios (4 archivos)

### 1. `src/actions/asistencia.actions.ts` — `getHistorialAsistencia()`
**Security-critical: server-side filtering**

Después de obtener la sesión (línea ~378), añadir:
```typescript
const userRole = (session.user as { role?: string })?.role || "empleado";

if (userRole === "empleado") {
  const [emp] = await db
    .select({ id: empleado.id })
    .from(empleado)
    .where(eq(empleado.userId, session.user.id))
    .limit(1);

  if (!emp) {
    return { success: true, message: "Sin perfil de empleado", data: { registros: [] } };
  }

  conditions.push(eq(resumenAsistenciaDiaria.empleadoId, emp.id));
}
```

Esto garantiza que un empleado jamás vea datos de otros empleados, incluso si manipula los parámetros en el cliente.

### 2. `src/actions/asistencia.actions.ts` — `getEmpleadosActivos()`
**Filtrar datos que alimentan el selector de empleados**

Después de obtener la sesión (línea ~455), añadir:
```typescript
const userRole = (session.user as { role?: string })?.role || "empleado";

if (userRole === "empleado") {
  const results = await db
    .select({ ... })
    .from(empleado)
    ...
    .where(and(eq(empleado.estado, "activo"), eq(empleado.userId, session.user.id)))
    ...
  return { success: true, message: "...", data: { empleados: results } };
}
```

### 3. `src/app/dashboard/asistencia/page.tsx` — Server component
- El `userRole` ya está disponible (línea 78).
- Evitar fetches innecesarios cuando el usuario es empleado: no llamar a `getSucursales()` ni `getEmpleadosActivos()` (el backend ya filtrará, pero es optimización limpia).
- Pasar `esEmpleado` como prop a `AsistenciaManager`.

```typescript
const esEmpleado = userRole === "empleado";
const sucursalesData = esEmpleado ? [] : ((sucursalesResult.data as ...)?.sucursales || []);
const empleadosData = esEmpleado ? [] : ((empleadosResult.data as ...)?.empleados || []);

return (
  <AsistenciaManager
    historialInicial={historialData}
    sucursales={sucursalesData}
    empleados={empleadosData}
    esEmpleado={esEmpleado}
  />
);
```

### 4. `src/components/modules/asistencia/asistencia-manager.tsx` — Client component
- Añadir prop `esEmpleado?: boolean`.
- Cuando `esEmpleado === true`:
  - Ocultar toda la barra de filtros + acciones (search, fechas, sucursal, "Buscar", "Corte automático", "Registro manual") — líneas 227—287.
  - Mantener solo la tabla de historial (Card con los registros).

---

## Resumen de seguridad
- El filtrado principal ocurre **en el servidor** (action), no en el cliente.
- La UI es solo una capa cosmética adicional; aunque un empleado manipule el frontend, el action nunca retornará datos ajenos.
- No se necesita modificar la tabla/schema de BD.
